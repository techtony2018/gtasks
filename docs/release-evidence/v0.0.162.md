## Change

Dashboard-managed Goal execution canary mode now accepts an explicit private
runtime target value of `auto`. Auto canary still activates at most one
Goal-derived Agent Task per run, but chooses the first currently
`auto_eligible` Goal instead of staying pinned to a fixed completed Goal.

When no Goal is newly eligible, the public status selects the most relevant
current canary state in this order:

1. active accepted handoff,
2. newest recently completed derived Task,
3. verified attention/blocker state.

This keeps unrelated `waiting_for_tony` or infrastructure blockers visible in
the decisions list without hiding live automatic progress.
