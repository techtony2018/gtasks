# V0.0.216 — Prioritize completed inbox receipts over stale blocked acks

## Scope

- Product commit:
  `98a70502226dc2cd7181218d22172c3bd179b8e5`.
- Remote handoff workers now check for a completed local wake-inbox result
  before retrying an older pending `still_blocked` acknowledgement.
- When the completed receipt is verified, Mission Control submits the
  completed acknowledgement and clears the pinned Agent claim so the next
  Goal-derived task can proceed.
- Dashboard-managed `/api/health` and `/api/releases` read back V0.0.216.

## Remote worker fleet verifier

Use the fleet verifier as the post-repair readback gate:

```bash
python3 scripts/verify_handoff_worker_fleet.py \
  --inventory config/handoff-dispatcher/remote-workers.json
```

Expected PASS means every configured remote Codex worker verifies on its own
host with:

- `ok: true`
- expected `hosts/<agent>` private route
- current repo HEAD
- preflight verification
- LaunchAgent readback when configured
- required private Artifact publisher token/config

## Boundaries

- Timmy/Toddy remain remote-only workers.
- This Mac's local supervisor remains Tammy/Tammy-OC only.
- Fleet PASS is remote-host health; it is not permission to run Timmy or Toddy
  locally.
- Completed wake-inbox precedence requires verified completed readback and does
  not fabricate Artifact publication or bypass private token/config
  requirements.
