## Behavior and limits

- A monotonic overall refresh deadline includes admitted queue time,
  dependency waits, OAuth locks and canonical transport work. Fast foreground
  refresh still returns a fresh value; slow refresh returns last-verified data
  with a terminal, recoverable state. Per-call timeouts cannot reset the budget.
- Running workers and queues are bounded. Old or canceled generations cannot
  publish over replacements. Uncooperative remote/Python calls cannot be killed
  safely; they retain occupied slots until they return. This is bounded impact,
  not a claim of remote cancellation.
- Archived-only task TODO enrichment is skipped in summary views, with explicit
  `todos_deferred` metadata in every summary representation. Active enrichment
  and canonical archived detail remain available. No false empty-TODO claim.
- Selected Tasks/Projects/Agent Work/Open System Tickets freshness is labeled
  independently. Inbox labels Tasks and Proposals separately. Missing/future
  timestamps do not become invented verification. One60-second text-only age
  update does not fetch, rerender cards or move focus.
- Cached project cards survive terminal errors; Tasks transport failure removes
  an old fresh claim while keeping its payload and timestamp. Explicit retry
  uses the selected read endpoint and existing request coalescing.
