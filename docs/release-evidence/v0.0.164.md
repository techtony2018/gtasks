# Mission Control V0.0.164 — Recover expired Agent execution claims

Date: 2026-08-24

## Scope

- Recover an expired owned `execution_claim` when the same registered Agent host polls again.
- Preserve the host-local worker boundary: this Mac's local supervisor remains responsible only for the local Tammy/Tammy-OC pair. Timmy and Toddy workers belong on their own host machines and must not be installed as local workers here.
- Do not print or persist dispatcher secrets in release evidence.

## Root cause

A Goal-derived Toddy task had a durable queued handoff and an active execution claim whose `expires_at` had passed. The local dispatcher claim path filtered candidates with `e.expires_at > now`, so the stale claim was neither leased nor terminalized/recovered at the next poll. That left the handoff stuck as queued even after the correct worker infrastructure was restored.

## Fix

At the authenticated claim boundary, Mission Control now detects an expired owned execution claim that still has verified current task authority and refreshes that execution fence before leasing the handoff to the same registered local dispatcher. The repair is scoped to owned execution only; delegated execution still keeps its stricter checkpoint/handback rules.
