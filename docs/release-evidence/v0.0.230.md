# V0.0.230 — Keep task edits ahead of older refreshes

Iteration 1 of the September 7 Mission Control reliability/enjoyment plan.

## Changes

- Invalidation revokes the current refresh generation and releases its loading
  ownership, allowing the next canonical read to replace it immediately.
- Existing generation checks reject obsolete success, failure and cleanup.
- Snapshot persistence has a serialized lane; each writer captures current
  records after acquiring that lane. An older save cannot finish after a newer
  save and replace the latest private cache on disk.
- Canonical storage and transport remain GBrain remote MCP. No task data is
  changed as part of the repair or tests.

## Targeted regression evidence

Four new tests failed on the corresponding unfixed behavior, then passed after
implementation: replacement/readback ordering, invalidation before completion,
obsolete failure versus replacement loading, and overlapping disk persistence.

The cache suite and affected HTTP surface tests are the iteration gate. They use
temporary snapshots and synthetic adapters, never production write benchmarks.

## Release gate

Candidate verification, independent QA, commit and deployed readback are recorded
in the iteration plan. This file describes the candidate; it does not itself
claim deployment.
