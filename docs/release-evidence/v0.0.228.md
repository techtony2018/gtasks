# V0.0.228 — Scope dispatcher handoff attention to Agent-authorized tasks

## Scope

- Direct implementation request from Tony; no System Ticket was created or
  reopened for this repair.
- Affected normal Tony task:
  `tasks/5d075e51-5407-4acd-8af9-fa9f2e1f1b59`.
- Classification: task-detail projection/editability repair.
- No Tony personal tasks, goals, projects, task relationships, or handoff
  history rows are mutated by this release.

## Root cause

`exact_task_api_payload()` added `dispatcher_handoff` from
`handoff_store.latest_task_handoff_status(task_slug)` to every non-completed
task detail payload. That made old suppressed dispatcher events appear as
current repair attention on ordinary Tony tasks whose canonical `owner_agent`,
`handoff`, and `goal_derivation` fields were all absent.

The task list projection was already clean because it does not decorate normal
Tony task rows with dispatcher handoff status.

## Behavior

Exact task detail now projects dispatcher handoff repair attention only when
the canonical task has explicit Agent execution authority:

- `owner_agent` is an Agent slug;
- canonical `handoff.resume_owner` is an Agent slug; or
- `goal_derivation` is present.

Ordinary Tony tasks with stale suppressed handoff history remain editable.
Agent-owned task detail and Agent Work projections still surface dispatcher
recovery evidence.
