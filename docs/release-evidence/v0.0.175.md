# V0.0.175 — Prioritize recoverable Goal handoffs

## Scope

- Auto canary selection now prefers a verified recoverable `handoff_needs_repair` task over a separate `waiting_for_tony` blocker.
- The priority lift applies only when the existing task is active/planned, Goal-derived, has an explicit next action, is not waiting on Tony, and its delivery state is a recoverable suppressed checkpoint/expiry.
- Non-recoverable handoff repair, missing-next-action, and waiting-for-Tony states keep their existing visible attention/blocker semantics.
