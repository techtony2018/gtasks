## Verified behavior

`/api/agent-work` now includes the latest dispatcher handoff status for
non-completed Agent task rows as `dispatcher_handoff` when the handoff store
has readback evidence and the canonical task `handoff` field is empty. This is
a read-only projection for operator visibility. It does not overwrite or
create canonical `handoff` content.

Completed Agent-work rows suppress `dispatcher_handoff` so old dispatcher
evidence does not imply current executable work.

Independent QA verified the behavior on desktop `1440x1000` and genuine mobile
`390x844` using a source-blind intercepted fixture where canonical
`handoff: null` and server-projected `dispatcher_handoff: {status:
"completed"}` were the only detail fallback. Agents current-work and Board
Agent card fallback details showed `Verified Agent handoff needs system
review` plus latest dispatcher status copy, while canonical `handoff` remained
null. QA also verified completed-row suppression and exact Task detail
regression behavior.

Live readback: Civic Agent-work task
`tasks/7ad5e1f5-eeb3-5fcf-850f-580eadb4ce92` was active with canonical
`handoff: null` and `dispatcher_handoff: {"status": "completed"}`.

## Boundary

`dispatcher_handoff` is projection evidence only. It must not be documented as
canonical task `handoff`, as authorization to fabricate delivery, or as
completion of a non-completed task.
