## Verified behavior

Goal execution WIP accounting now ignores active Agent tasks that are
themselves missing explicit execution instructions: blank `next_action`, no
canonical `handoff`, no blockers or dependencies, and no open TODO. A stalled
`task_needs_next_action` item remains visible as Needs attention but does not
by itself block another bounded Goal review from becoming `auto_eligible`.

Control behavior remains strict: actionable active Agent work with a real
`next_action` still consumes WIP and can keep another Goal at `wip_full`.

Independent QA verified the behavior on desktop `1440x1000` and genuine mobile
`390x844` with source-blind fixtures. The stalled-work fixture rendered one
Goal as `task_needs_next_action` and the second Goal as Ready /
`auto_eligible`; the control fixture changed only the unrelated active task to
an actionable explicit next action and the second Goal rendered blocked by the
work-in-progress limit.

## Boundary

This release changes WIP accounting only. It does not complete, repair, or
make actionable the stalled `task_needs_next_action` task, and it does not
relax WIP for active Agent tasks that already have a real next action.
