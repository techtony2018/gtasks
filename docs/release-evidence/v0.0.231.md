# V0.0.231 candidate — Retain task drafts and protect retries

Iteration 2 of the September 7 reliability/enjoyment plan. Code review and
independent managed pre-commit UI QA have passed. Release deployment receipts
are recorded below when verified.

## Behavior

- Ordinary Create sends a stable operation identity. Its private journal
  contains request hashes and operation receipts, not canonical task text.
- Verified retries read the original canonical task without rewriting it.
  Changed requests conflict. Uncertain writes expose the original task and
  do not replay a potentially completed write.
- The browser retains the last submitted creation draft and identity across
  reloads where session storage works. Storage failures must preserve an
  in-tab fallback and explain the reload limitation.
- Edit reads the canonical task when opened, captures its revision and
  preserves the draft if later canonical state conflicts. Existing event
  progress revision protection must remain functional.
- GBrain remains authenticated remote MCP. The current remote tools expose
  no atomic conditional write; these checks are optimistic stale-edit
  protection, not atomic protection against simultaneous independent writers.
