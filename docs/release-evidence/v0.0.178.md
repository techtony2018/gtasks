# V0.0.178 — Bound Agent Work refresh latency

## Scope

- `/api/agent-work` now uses the shared read-surface cache:
  - cold reads return bounded `202`/`loading` instead of blocking on a slow canonical scan;
  - warm reads return labeled last-verified data while a refresh runs;
  - task mutations invalidate the Agent Work surface alongside the main task/proposal surfaces.
- Agent Work reads still return completed and cancelled Agent-owned tasks for recent-completion/history context.
- Completed and cancelled tasks no longer hydrate TODO backlinks during the Agent Work read.
- Active, planned, blocked, and other non-terminal Agent work still hydrate TODOs so current work and open next actions remain visible.
- This reduces refresh fan-out without hiding current Agent work or verified completion history.
