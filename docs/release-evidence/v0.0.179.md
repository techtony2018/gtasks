# V0.0.179 — Expose active Goal handoff state

## Scope

Goal execution already selected and rendered Goal-derived Agent work, but the
top-level `/api/goal-execution` headline could still say `duplicate` even when
the selected canonical task had a verified queued or actively executing
handoff. That made real Agent progress look like stalled duplicate work to
operators and automations.

V0.0.179 keeps the per-decision diagnostic reason as `duplicate`, but projects
the public headline as:

- `delivering` for queued, leased, or retrying handoffs;
- `actively_executing` for received, acknowledged, processing,
  agent-working, or actively executing handoffs.

The Agents UI copy now mirrors that distinction for duplicate decisions whose
selected task matches the latest verified handoff.
