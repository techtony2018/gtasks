# Mission Control V0.0.100 release evidence

## Scope

Canonical System Ticket:
`tasks/cadd4182-7102-4996-b169-d25539721411` — diagnose and fix the
Chrome-tab-specific Mission Control UI freeze.

The fix is intentionally limited to automatic-refresh scheduling. It does not
change GBrain data, task lifecycle behavior, or the visible stale/fresh state.

## Exact long-open Chrome diagnosis

The affected page was the existing Mission Control target in the Chrome CDP
profile on `127.0.0.1:9333`. Diagnosis did not reload the page or mutate GBrain.
The renderer stayed near 95% CPU with RSS near 1,076,896 KiB. A five-second
Chrome Performance/Profiler sample recorded:

- an overdue automatic-refresh deadline of `-26,876,243 ms`;
- `tasksReadState.refreshing=true` and `stale=true`;
- 303 layouts and 303 style recalculations;
- 636 additional event listeners and 9,100 additional retained nodes;
- 3.528 seconds of main-thread task duration;
- zero active CSS animations;
- the hottest application path as
  `performTaskLoad -> render -> renderBoard -> boardCard -> relativeDue`.

The root cause was the interaction between these two valid states: a
stale/refreshing response preserved the old auto-refresh deadline, while that
deadline was already in the past. `scheduleAutoRefresh()` therefore armed a
0ms timer after every successful read. The separate one-second stale-surface
poll was not the runaway source. CSS animation was also ruled out.

## Repair and automated bounds

`scheduleAutoRefresh()` now advances a missing, reset, or expired deadline to
the next normal 30-minute interval. The existing one-second stale-surface poll
remains unchanged.

The runtime contract tests cover the original 26,482,161ms-overdue state and a
120-cycle stale/refreshing soak. The soak requires, per cycle:

- one read and one render;
- one 1,000ms stale-surface timer;
- one 1,800,000ms automatic-refresh timer;
- zero 0ms timers and no unexpected timer growth.

## Independent pre-commit gate

The frozen uncommitted candidate must be checked at desktop `1440x1000`, a
genuine `390x844` mobile viewport, and the preserved Chrome CDP 9333 profile.
The independent report is stored under
`artifacts/qa/v0.0.100-ui-freeze-independent/`.

The CDP soak uses privacy-safe aggregate metrics only. Over a five-second
steady-state sample it must show: no overdue auto-refresh deadline, no 0ms
refresh loop, no more than 10 layouts/style recalculations, no more than 30 new
listeners, no more than 500 retained nodes, and no more than 1.0 second of task
duration. The original tab may be reloaded only after its pre-fix trace is
preserved, because already-loaded JavaScript cannot receive the scheduler fix
without loading the new asset. The report must state that reload explicitly.

Commit remains blocked until the independent report returns explicit PASS.
