# V0.0.227 — Reduce direct task hydration fan-out

## Scope

- System Ticket: `tasks/9f165073-4505-4e11-a473-dccf21e0bfa2`.
- Classification: direct canonical task read-path performance repair.
- No Tony business tasks, goals, projects, proposals, or task relationships are
  mutated by this release.

## Root cause

`GBrainAdapter.list_collection_tasks()` already read the lifecycle root
backlinks, but then hydrated each typed task member with both `get_page` and
`get_links`. For active Tony tasks this produced 37 remote MCP calls for 18
tasks: one root backlink call plus 18 page reads plus 18 relationship reads.

Typed `member_of` backlinks already verify lifecycle membership, and each task
page frontmatter carries the relationship projection used by the dashboard.
The extra per-task `get_links` call was therefore unnecessary for typed
members.

## Behavior

V0.0.227 changes collection reads for typed members:

- use the root `member_of` backlink as the verified lifecycle edge;
- project task frontmatter `links` into read-only edge records for domain
  parsing;
- skip per-task `get_links` calls for typed members;
- keep legacy untyped memberships on the old `get_links` fallback path.

This preserves visible project, goal, parent, dependency, and blocker
projections while reducing direct active/completed task root fan-out.
