# V0.0.223 — Refresh System Tickets from bounded canonical metadata

## Scope

- Release commit:
  `559c3a7f88d200472069791628595ed323218723`.
- System Ticket:
  `tasks/e5ad43ee-aaad-4313-a798-ae4058dba9ac`.
- `GBrainAdapter.list_system_tickets` now combines typed collection-root
  backlinks, bounded `list_pages` `updated_at` metadata, and the last-verified
  `system_tickets_all` snapshot.
- `RemoteHttpCommandRunner` now honors the owner-only path supplied through
  `GBRAIN_CREDENTIALS_FILE` when `GBRAIN_HOME` selects a `remote_mcp` config.
  No credential value is stored in this evidence.

## Read contract

- Typed backlinks to `collections/mission-control-system-tickets` remain the
  membership authority.
- An unchanged member may reuse its last-verified snapshot projection only
  when bounded remote metadata does not show a newer canonical page.
- Changed or snapshot-missing members are hydrated from canonical pages, so a
  completed ticket reopened to planned/active is still detected.
- Missing, invalid, or unusable snapshot/metadata evidence falls back to page
  hydration. The cache remains a read projection, never canonical state.

## Security and authority boundary

`GBRAIN_CREDENTIALS_FILE` names an owner-only runtime file. It is not a secret
value itself, and the file contents must never be embedded in repository
configuration, source, logs, receipts, or documentation. This release changes
credential discovery and read efficiency only; it grants no new GBrain write,
task-lifecycle, System-Ticket creation, or raw-write authority.
