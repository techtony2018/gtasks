## Verified behavior

Goal execution now distinguishes active or planned non-derived Agent goal
tasks that cannot be executed because they lack an explicit next action. A
task projects as `task_needs_next_action` when it is active or planned, linked
to a Goal, not goal-derived, has blank `next_action`, has no canonical
`handoff`, has no blockers or dependencies, and has no open TODO.

The UI renders that decision as Needs attention with exact copy:

`The canonical task is active, but it has no explicit next action for the assigned Agent.`

Actionable `duplicate`, passive scheduled waits, `handoff_missing`, terminal
`handoff_needs_repair`, and `recently_completed` remain separate states with
their existing copy and behavior.

Independent QA verified the behavior on desktop `1440x1000` and genuine mobile
`390x844` with source-blind multi-goal fixtures. It also verified keyboard
activation, Task detail focus/close restore, mobile focus trap, and distinct
regression states for duplicate, missing handoff, handoff repair, and recently
completed decisions.

## Boundary

`task_needs_next_action` is an instruction-gap projection. It does not create
or repair the missing next action, handoff, blocker, dependency, or TODO. Do
not merge it with ordinary duplicate, passive scheduled wait, missing handoff,
handoff repair, or recently completed states.
