## Creation contract

Before writing a normal task, `POST /api/tasks` reads the requested
owner/lifecycle root and compares open tasks using all of these fields:

- normalized title;
- `due_day`;
- Project;
- Goal;
- parent.

One match returns HTTP `409` with `code=duplicate_task_exists`,
`duplicate=true`, and the existing canonical task projection. The client may
adopt that task; the server performs no task or TODO write. Multiple matches
return HTTP `409` with `code=ambiguous_duplicate_task`, the matching task
projections, and no write. Completed and cancelled tasks are excluded.

The repository `mc-add-task` helper applies the same pre-write match. One
match is canonically read back and returned with `action=adopted_existing`;
multiple matches return `action=ambiguous_duplicate` and exit without a
write. The helper now uses the default remote-MCP `GBrainAdapter`, accepts
`--project-slug` and `--goal-slug`, and verifies Project `member_of` plus Goal
`advances_goal` links.

## Authority boundary

This guard applies only to normal task creation. It does not merge existing
tasks, mutate canonical task fields, choose among ambiguous matches, create or
complete System Tickets, or authorize changes to Tony's business tasks. A
duplicate or ambiguity response is a readback result, not a successful new
write receipt.
